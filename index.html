# 衡策｜量化策略研究平台

衡策是一套將**市場資料、策略研究、歷史回測、研究驗證與決策輔助**整合在同一系統中的量化研究平台。

系統以實際歷史行情為基礎，在一致的資料可見範圍、成交時點與交易成本下比較不同策略，並特別處理前視偏誤（look-ahead bias）、資料缺漏、企業行動、參數尋優以及策略改版造成的績效退化。

> 專案目標不是找出歷史報酬最高的策略，而是建立一套**可重現、可驗證、可比較、可追溯**的研究流程。

目前研究範圍包含臺灣 50 系列、金融股策略，以及臺指選擇權買方策略。部分金融與衍生商品研究仍屬 Beta／研究觀察階段，不代表正式投資建議。

---

## 專案重點

這個專案不只實作技術指標或單一回測公式，而是將策略研究視為一個需要長期維護的工程系統。

核心設計包含：

- 不同策略使用一致的時間範圍、成交假設與成本模型比較。
- 訊號只能使用決策當下已完成、當時可取得的資料。
- ETF、股票與選擇權使用各自實際行情，不用其他商品報酬人工合成。
- 手續費、交易稅、滑價／價差等交易成本納入績效。
- 對行情來源建立資料閘門、快取、續傳、降級與缺漏修復機制。
- 策略或回測邏輯修改時，CI 會要求產生改版前後績效比較。
- 研究結果、integrity audit 與 performance report 保存在 repository 中。
- 對可能存在過度配適的結果保留研究觀察狀態，而不是直接升格為正式策略。

## Engineering Highlights

### 1. 防止 Look-ahead Bias

回測中的訊號產生與成交時點刻意分離。

```text
T-1 已完成資料
      │
      ▼
產生策略訊號
      │
      ▼
T / 下一可交易時點
      │
      ▼
執行部位調整
```

未完成的日 K、週 K、雙週 K、月 K 或季 K 不得提前進入策略判斷。

指定歷史回測截止日後，行情、指標、研究樣本與策略決策都必須同步截斷，不允許使用截止日之後的資料。

### 2. 真實商品行情，不使用合成捷徑

0050、00631L、00632R 與金融標的各自使用自己的實際歷史行情。

例如：

```text
錯誤做法
0050 daily return × 2
        ↓
模擬 00631L

衡策
00631L actual OHLCV
        ↓
Backtest
```

這避免忽略槓桿 ETF 的每日重設、波動耗損、複利路徑與實際交易價格。

### 3. Transaction-cost-aware Backtest

策略比較會納入：

- 券商手續費
- 商品適用的證交稅
- 滑價／價差隱含成本
- 實際進出場時點
- 整股或整數口數限制

績效指標包含：

- 累積報酬
- 年化報酬
- 最大回撤
- Sharpe Ratio
- Calmar Ratio
- 勝率
- 交易次數
- 成本拆分

買進持有作為比較基準，不直接參與主動策略首選。

### 4. Research Integrity 與 Performance Regression Guard

策略研究不是只比較「新版報酬有沒有比較高」。

repository 中保留：

```text
docs/
├─ research-preregistrations/
├─ strategy-integrity-audits/
├─ strategy-performance-reports/
├─ *-research.md
└─ *-protocol.md
```

策略計算或研究檔變更時：

```bash
npm run guard:strategy-performance
```

會要求產生新版／舊版的績效比較。

若新版報酬下降，研究結果必須留下原因與風險交換說明，例如：

- 維持舊版
- 保留新版為研究觀察
- 接受較低報酬換取較低回撤／較低頻率
- 判定沒有增量效益

避免策略邏輯改版後，歷史績效退化卻被靜默覆蓋。

### 5. Development / Validation / Holdout

部分研究採分段方式進行，例如：

```text
Historical Data
│
├─ 60% Discovery
│
├─ 20% Validation
│
└─ 20% Holdout / Out-of-sample
```

研究過程中也保留固定樣本、walk-forward、事件研究與 sensitivity test 等不同驗證方式。

README 不將單一歷史高報酬視為策略有效性的充分證據；實際研究證據以 `docs/` 中的 protocol、audit 與 performance report 為準。

### 6. Market Data Reliability

行情資料不是單純「API 有回就算成功」。

資料層會處理：

- 預期交易日與實際資料完整度
- 快取與缺漏月份補抓
- 中間缺日與尾端缺日
- 企業行動（split / reverse split）
- 官方資料交叉確認
- 資料源失效時的降級與告警
- 服務啟動時的 data gate

完整契約請參閱：

- [`docs/market-data-reliability.md`](docs/market-data-reliability.md)
- [`docs/data-maintenance-sop.md`](docs/data-maintenance-sop.md)

## Backtest Contract

README 僅保留最重要的回測契約；商品與策略的完整規則放在各研究文件中。

1. **只使用當時可見資料**  
   策略訊號不能讀取未來資料。

2. **訊號與成交時間分離**  
   完成資料產生訊號後，才在下一個合法成交時點執行。

3. **公平比較**  
   同一組策略比較使用一致的起訖日、資金、成本與 benchmark。

4. **交易成本不可忽略**  
   手續費、稅負、滑價與商品限制均納入。

5. **高週期資料必須完整收盤**  
   未完成的週／月／季資料不得提早進入判斷。

6. **商品使用自身實際行情**  
   不以其他商品報酬人工生成歷史價格。

7. **研究結果與正式策略分離**  
   少量樣本、高報酬或單一期間成功，不代表策略已通過正式研究門檻。

8. **歷史績效退化不可靜默覆蓋**  
   策略改版需留下 performance comparison 與研究決策。

更多限制與 guardrail 請參閱：

- [`docs/backtest-settings-guardrails.md`](docs/backtest-settings-guardrails.md)
- [`docs/option-native-strategy-research.md`](docs/option-native-strategy-research.md)
- [`docs/weekly-option-strategy-research.md`](docs/weekly-option-strategy-research.md)

衡策｜量化策略研究平台

衡策是一套將市場資料、策略研究、歷史回測、研究驗證與決策輔助整合在同一系統中的量化研究平台。

系統以實際歷史行情為基礎，在一致的資料可見範圍、成交時點與交易成本下比較不同策略，並特別處理前視偏誤（look-ahead bias）、資料缺漏、企業行動、參數尋優以及策略改版造成的績效退化。

專案目標不是找出歷史報酬最高的策略，而是建立一套可重現、可驗證、可比較、可追溯的研究流程。

目前研究範圍包含臺灣 50 系列、金融股策略，以及臺指選擇權買方策略。部分金融與衍生商品研究仍屬 Beta／研究觀察階段，不代表正式投資建議。

專案重點

這個專案不只實作技術指標或單一回測公式，而是將策略研究視為一個需要長期維護的工程系統。

核心設計包含：

  • 不同策略使用一致的時間範圍、成交假設與成本模型比較。
  • 訊號只能使用決策當下已完成、當時可取得的資料。
  • ETF、股票與選擇權使用各自實際行情，不用其他商品報酬人工合成。
  • 手續費、交易稅、滑價／價差等交易成本納入績效。
  • 對行情來源建立資料閘門、快取、續傳、降級與缺漏修復機制。
  • 策略或回測邏輯修改時，CI 會要求產生改版前後績效比較。
  • 研究結果、integrity audit 與 performance report 保存在 repository 中。
  • 對可能存在過度配適的結果保留研究觀察狀態，而不是直接升格為正式策略。

Engineering Highlights

1. 防止 Look-ahead Bias

回測中的訊號產生與成交時點刻意分離。

T-1 已完成資料
      │
      ▼
產生策略訊號
      │
      ▼
T / 下一可交易時點
      │
      ▼
執行部位調整

未完成的日 K、週 K、雙週 K、月 K 或季 K 不得提前進入策略判斷。

指定歷史回測截止日後，行情、指標、研究樣本與策略決策都必須同步截斷，不允許使用截止日之後的資料。

2. 真實商品行情，不使用合成捷徑

0050、00631L、00632R 與金融標的各自使用自己的實際歷史行情。

例如：

錯誤做法
0050 daily return × 2
        ↓
模擬 00631L

衡策
00631L actual OHLCV
        ↓
Backtest

這避免忽略槓桿 ETF 的每日重設、波動耗損、複利路徑與實際交易價格。

3. Transaction-cost-aware Backtest

策略比較會納入：

  • 券商手續費
  • 商品適用的證交稅
  • 滑價／價差隱含成本
  • 實際進出場時點
  • 整股或整數口數限制

績效指標包含：

  • 累積報酬
  • 年化報酬
  • 最大回撤
  • Sharpe Ratio
  • Calmar Ratio
  • 勝率
  • 交易次數
  • 成本拆分

買進持有作為比較基準，不直接參與主動策略首選。

4. Research Integrity 與 Performance Regression Guard

策略研究不是只比較「新版報酬有沒有比較高」。

repository 中保留：

docs/
├─ research-preregistrations/
├─ strategy-integrity-audits/
├─ strategy-performance-reports/
├─ *-research.md
└─ *-protocol.md

策略計算或研究檔變更時：

npm run guard:strategy-performance

會要求產生新版／舊版的績效比較。

若新版報酬下降，研究結果必須留下原因與風險交換說明，例如：

  • 維持舊版
  • 保留新版為研究觀察
  • 接受較低報酬換取較低回撤／較低頻率
  • 判定沒有增量效益

避免策略邏輯改版後，歷史績效退化卻被靜默覆蓋。

5. Development / Validation / Holdout

部分研究採分段方式進行，例如：

Historical Data
│
├─ 60% Discovery
│
├─ 20% Validation
│
└─ 20% Holdout / Out-of-sample

研究過程中也保留固定樣本、walk-forward、事件研究與 sensitivity test 等不同驗證方式。

README 不將單一歷史高報酬視為策略有效性的充分證據；實際研究證據以 docs/ 中的 protocol、audit 與 performance report 為準。

6. Market Data Reliability

行情資料不是單純「API 有回就算成功」。

資料層會處理：

  • 預期交易日與實際資料完整度
  • 快取與缺漏月份補抓
  • 中間缺日與尾端缺日
  • 企業行動（split / reverse split）
  • 官方資料交叉確認
  • 資料源失效時的降級與告警
  • 服務啟動時的 data gate

完整契約請參閱：

  • docs/market-data-reliability.md

Backtest Contract

README 僅保留最重要的回測契約；商品與策略的完整規則放在各研究文件中。

  1. 只使用當時可見資料
    策略訊號不能讀取未來資料。

  2. 訊號與成交時間分離
    完成資料產生訊號後，才在下一個合法成交時點執行。

  3. 公平比較
    同一組策略比較使用一致的起訖日、資金、成本與 benchmark。

  4. 交易成本不可忽略
    手續費、稅負、滑價與商品限制均納入。

  5. 高週期資料必須完整收盤
    未完成的週／月／季資料不得提早進入判斷。

  6. 商品使用自身實際行情
    不以其他商品報酬人工生成歷史價格。

  7. 研究結果與正式策略分離
    少量樣本、高報酬或單一期間成功，不代表策略已通過正式研究門檻。

  8. 歷史績效退化不可靜默覆蓋
    策略改版需留下 performance comparison 與研究決策。

資料與限制

日線主資料以 Yahoo Finance 為主要來源，並搭配證交所／期交所官方資料進行確認、補齊或研究。

對 ETF 的分割／反分割會依企業行動調整，避免把企業行動誤判成市場暴漲暴跌。

所有畫面上的策略判斷僅使用最近一個已完成交易時點的資料。即時行情、歷史回測行情與實際券商成交行情並不等價。

Yahoo Finance 與本專案中的行情資料均不應視為交易所保證的下單價格；實際交易前仍需自行確認市場與券商資訊。
