# 衡策｜量化策略研究平台

一套以相同資料、交易成本與成交時點，公平比較投資策略的 Vue + Node.js 量化研究與決策輔助平台。目前支援臺灣50系列、五個金融研究標的，以及只做買方的臺指選擇權 Call／Put。各商品各自使用實際行情、成本與基準；金融與臺指選擇權研究目前為 Beta、限 Admin 使用。

開發本專案前，請先閱讀 [`docs/development-guidelines.md`](docs/development-guidelines.md)；其中記錄共用元件索引、介面規格、互動原則與完成前的瀏覽器驗證要求。新增或修改行情來源時，另須遵守 [`docs/market-data-reliability.md`](docs/market-data-reliability.md) 的供應者介面、快取、續傳、降級與故障測試契約。

## 工程重點與驗證入口

本專案的工程核心是建立可比較、可追溯的研究流程：資料是否當時可見、交易是否真能在該時點成交、成本是否一致，以及改版是否有證據支持。AI 協助需求拆解、方案比較、實作、重構、測試與文件整理；計算口徑、驗收條件與風險交換由我決定，再以測試、研究文件與交付閘門核對。

### 研究結果的解讀邊界

多週期條件研究採 60%／20%／20% 切分；其他研究以各自 protocol 為準，不能把所有頁面績效一律稱為樣本外結果。通用附加尋優選定參數後呈現完整範圍，包含選參資料；事後排名與已見近期稽核需揭露其限制，不等同可交易驗證。金融與選擇權的 Beta／研究觀察狀態也應和正式策略分開。

## 執行

需求：Node.js 20 以上版本。

完整的開發、測試與部署規範以 [`docs/development-guidelines.md`](docs/development-guidelines.md) 的「現行開發與公開運行模式」為準。

### 本機互動開發

```bash
npm install
npm run dev
```

開啟 `http://localhost:5173`。開發模式的前後端都只監聽本機回環位址，並同時啟動：

- Vue 前端：`http://localhost:5173`
- Node.js API：`http://localhost:8787`

不再提供區域網路直連或 Windows 5173 portproxy。手機一律使用 ngrok 公開網址，不得為手機測試重新開放 Vite 或後端埠。

本機開發與常駐公開服務共用行情快取及 SQLite；執行 `npm run dev` 前應先停止 `hengce-public.service`，避免兩個後端同時執行。

### 正式公開模式

人工前景啟動：

```bash
npm run public:secure
```

目前正式常駐採 `ngrok HTTPS Tunnel → Nginx 18787 → Unix Socket → Node`，Google OAuth 驗證、系統登入白名單、Admin 權限與裝置 Session 全由 Node 後端處理。Node 不監聽任何 TCP 埠，只有 Nginx 能經權限設為 `0600` 的 Socket 代理 API；由 systemd 啟動並以健康 timer 自動修復。安裝、白名單、Admin 設定、重啟、登出與故障排查請見 [`docs/public-google-sso.md`](docs/public-google-sso.md)。開發分支 commit 後執行 `npm run deliver:main`，即可由 GitHub Actions 或本機備援完成驗證、安全快轉 `main`、部署與 API 稽核；機器只回傳精簡 JSON 摘要，完整日誌保留在 `.runtime/release/`。

### 版本化簽署與使用權限

首頁可公開瀏覽，不要求 Google SSO 或簽署。進入策略研究時，系統先完成 Google OAuth 與系統登入白名單驗證，再檢查單一裝置 Session；只有 `設定的管理者帳號` 具備 Admin 權限，其餘白名單帳號都是一般使用者。登入完成後才讀取 `/api/consents/current`。只要任一必填項目尚未同意目前版本，畫面就會顯示不可關閉的簽署視窗，策略研究 API 也會回傳 `428 CONSENT_REQUIRED`；後端成功保存整包簽署結果後才開放使用。

- 現行項目、必填／選填、版本、上架時間與原文集中於 `shared/consent-definitions.ts`。
- 每次提交都保存整包項目，包含同意或拒絕、版本、簽署時間與當版原文；自己的歷史紀錄可由 `/api/consents/history` 查詢。
- 必填項目推出新版會要求所有使用者重新簽署；只有選填項目更新時不會中斷使用。
- SQLite 紀錄預設保存在 `server/.cache/user-consents.sqlite`，舊版原文與最初上架時間不會被新版覆寫。

## 回測規則

1. 策略在 T-1 日資料完整後產生目標曝險。
2. T 日開盤才執行部位調整；回測結束日預設為台北當天，尚未收盤或非交易日時以最近已取得日 K 的交易日為實際截止日。
3. 曝險可為 0%、25%、50%、75% 或 100%，不放空、不融資。
4. 每次部位變化依方向扣除手續費、賣出證交稅及滑價。
5. 期末結清預設關閉，持倉按期末行情估值；只有啟用時才平倉並將賣出成本計入績效。
6. 所有策略使用同一個起訖日、資金與成本設定。
7. 日 K 期望值策略以相似的趨勢、RSI、波動及相對強弱狀態估算未來持有期；每個歷史判斷只能使用當時以前已完成的樣本。
8. 可執行首選須有正年化報酬、最大回撤不超過 30%、Sharpe 大於零，且完整交易次數通過所選回測期間的動態門檻。
9. 週／雙週／月 K 訊號在高週期 K 棒完整收盤後產生，下一交易日開盤才調整部位。
10. 多週期條件研究的週、雙週、月、季 K 只採用完整 K 棒；買進與賣出勝率都以次日開盤執行並扣除來回成本。
11. 附加部位調整先取得原策略目標，再依單日漲跌調整；高波動選項會額外執行一次相同調整，最終曝險限制在 0%～100%。買進持有基準不套用附加層。
12. 留空結束日代表最新資料；指定結束日後，行情快照、訊號、回測、退場與多週期研究全部截斷於該日，不使用任何之後資料。資料不足完整期間與指標暖機時會拒絕執行。
13. 定期定額於回測區間第一天及之後每週／每月第一個交易日投入。定期／條件領回可建立至多五條具名規則並調整順序；每條的每 N 個月與帳面門檻是可同時啟用的 OR 條件，同日多條符合時只執行排序最前者。門檻以前一完整交易日的總資產帳面價值／帳面現金跨越「原始投入比例或固定金額」判斷；帳面現金包含另列且尚未投入的現金配息，門檻跌破後才重新待命。下一交易日開盤執行時，總資產模式可賣出持倉並計入賣出成本，帳面現金模式不賣持倉且領回額不超過現金。每次領回可用所選帳面價值的比例或固定金額計算。最低保留資金由獨立開關控制，也可建立至多五條具名規則；它不判斷每 N 個月，只在領回發生時依所選帳面價值由上到下套用第一條「每次」或「達門檻」的下限，沒有符合條件時不加下限。比例模式保留「執行當下所選帳面價值 × 比例」與「起始投入 × 同一比例」較高者，固定金額模式直接保留設定金額，賣出成本也不得侵蝕這次領回的保留底線。投入與領回都屬外部資金流：TWR 在領回執行點前後切分當日報酬再連乘，排除資金流但保留必要賣出成本；最大回撤使用資金流調整後淨值；XIRR 將投入列為負現金流、領回與期末資產列為正現金流。價格獲利固定為「期末價格資產＋由價格帳本支付的領回－起始資金－定期投入」；直接領回配息不會再算一次價格獲利。
    這項領回設定適用所有研究標的（包含臺指選擇權），且與商品是否實際配息無關。選擇權總資產模式只能以執行日實際開盤權利金賣出足夠整數口數；沒有可驗證開盤價時不偽造成交。
14. 自動尋優預設用較早 70% 歷史尋優區間比較 481 種附加方案，使用者可調整左右端，右端最高可到最後一個交易日，區間最短不得少於 2 年。選定後將同一方案套用到完整回測範圍；總報酬、年化報酬、勝率、Sharpe、回撤、品質分、排行榜與資格皆使用完整範圍。自動開啟時手動設定停用且不加入候選；關閉自動後才套用保留的手動參數。
15. KD 第 9 根日 K 起計算 RSV、K、D；MACD 需完成 26 日慢線與 9 日訊號線暖機後才產生部位，所有訊號皆於次日開盤成交。
16. 曲線與策略排名採純價格報酬：0050 分割前的價格與成交量會按分割比例還原；^TWII 使用加權價格指數。現金配息依策略在除息日前的實際持有部位另計，不重投、不改變資產曲線與策略排名；儀表板收合摘要另以配息留在現金部位的方式逐日計算含息總報酬、含息年化與相對0050績效。配息為稅前估算，未扣個人稅負與補充保費。
17. 月 MACD × K 策略只使用已完成的加權指數月 K：MACD（12、26、9）柱狀體負轉正後於下一交易日開盤買進 0050；持有後月 DIF 達 400 且月 K（9,3）達 76 時啟動退場偵測，之後任一跌破門檻即於下一交易日開盤賣出；D 值不參與。
18. 10% 大漲／大跌高低點必須等反向走勢確認後才能回頭標記，因此只作事件研究，不當成可交易訊號；實際族群策略仍以 T-1 已完成 K 棒產生訊號、T 日開盤成交。
19. 年度產業權重採前一年底資料避免前視偏誤。電子是半導體、電腦週邊、光電、通信網路、電子零組件、電子通路、資訊服務、其他電子八類合計；金融在 15 年內曾超過 10%，即使 2026 年基準降到 9.68% 仍保留獨立模型；其餘歸入非金電。
20. 0050、00631L、00632R 各自獨立使用實際行情、上市日、企業行動、成本、基準與工作區。正 2／反 1 是單日曝險目標，跨日報酬會受每日重設、波動耗損與複利路徑影響；歷史行情不得以 0050 日報酬直接乘以 2 或 -1 合成。00631L 的買進持有基準、均線、報酬、RSI、波動與回撤一律標示為 00631L；只有智能策略明確共用的 0050 完成 K 棒與成交量欄位保留「共用指標｜0050」標示。
21. `T50COMBO` 為獨立的臺灣50三資產輪動研究：使用0050、00631L、00632R三檔真實行情的共同交易日與一個共同資金池，不借款、不放空，權重合計不超過100%。三檔各自在每個年度開始前，以當時可見資料及個別風險承受門檻淘汰不合格正式策略，再封存年度首選；沒有合格者時該子標的不可用。0050與正2作互斥正向輪動，只有兩者都空手時反1首選才能接手；反1不是與多頭並存的持股避險。每個子策略保留自己的原始進退場政策，只有反1場景快攻使用預掛停利／停損，智能2.0反向鏡像則依鏡像期望優勢失效訊號退出。T日完成資料決定目標，T+1共同交易日開盤先賣後買，逐檔以實際價格、整股、手續費、ETF賣出稅及滑價記帳；0050配息留在現金。比較基準固定為同期100%持有0050。

執行

需求：Node.js 20 以上版本。

完整的開發、測試與部署規範以 docs/development-guidelines.md 的「現行開發與公開運行模式」為準。

本機互動開發

npm install
npm run dev

開啟 http://localhost:5173。開發模式的前後端都只監聽本機回環位址，並同時啟動：

  • Vue 前端：http://localhost:5173
  • Node.js API：http://localhost:8787

不再提供區域網路直連或 Windows 5173 portproxy。手機一律使用 ngrok 公開網址，不得為手機測試重新開放 Vite 或後端埠。

本機開發與常駐公開服務共用行情快取及 SQLite；執行 npm run dev 前應先停止 hengce-public.service，避免兩個後端同時執行。

正式公開模式

人工前景啟動：

npm run public:secure

目前正式常駐採 ngrok HTTPS Tunnel → Nginx 18787 → Unix Socket → Node，Google OAuth 驗證、系統登入白名單、Admin 權限與裝置 Session 全由 Node 後端處理。Node 不監聽任何 TCP 埠，只有 Nginx 能經權限設為 0600 的 Socket 代理 API；由 systemd 啟動並以健康 timer 自動修復。安裝、白名單、Admin 設定、重啟、登出與故障排查請見 docs/public-google-sso.md。開發分支 commit 後執行 npm run deliver:main，即可由 GitHub Actions 或本機備援完成驗證、安全快轉 main、部署與 API 稽核；機器只回傳精簡 JSON 摘要，完整日誌保留在 .runtime/release/。

版本化簽署與使用權限

首頁可公開瀏覽，不要求 Google SSO 或簽署。進入策略研究時，系統先完成 Google OAuth 與系統登入白名單驗證，再檢查單一裝置 Session；只有 設定的管理者帳號 具備 Admin 權限，其餘白名單帳號都是一般使用者。登入完成後才讀取 /api/consents/current。只要任一必填項目尚未同意目前版本，畫面就會顯示不可關閉的簽署視窗，策略研究 API 也會回傳 428 CONSENT_REQUIRED；後端成功保存整包簽署結果後才開放使用。

  • 現行項目、必填／選填、版本、上架時間與原文集中於 shared/consent-definitions.ts。
  • 每次提交都保存整包項目，包含同意或拒絕、版本、簽署時間與當版原文；自己的歷史紀錄可由 /api/consents/history 查詢。
  • 必填項目推出新版會要求所有使用者重新簽署；只有選填項目更新時不會中斷使用。
  • SQLite 紀錄預設保存在 server/.cache/user-consents.sqlite，舊版原文與最初上架時間不會被新版覆寫。

測試採紅燈、綠燈、重構流程；新增或修正回測規則時，應先建立失敗案例。

回測規則

  1. 策略在 T-1 日資料完整後產生目標曝險。
  2. T 日開盤才執行部位調整；回測結束日預設為台北當天，尚未收盤或非交易日時以最近已取得日 K 的交易日為實際截止日。
  3. 曝險可為 0%、25%、50%、75% 或 100%，不放空、不融資。
  4. 每次部位變化依方向扣除手續費、賣出證交稅及滑價。
  5. 期末結清預設關閉，持倉按期末行情估值；只有啟用時才平倉並將賣出成本計入績效。
  6. 所有策略使用同一個起訖日、資金與成本設定。
  7. 日 K 期望值策略以相似的趨勢、RSI、波動及相對強弱狀態估算未來持有期；每個歷史判斷只能使用當時以前已完成的樣本。
  8. 可執行首選須有正年化報酬、最大回撤不超過 30%、Sharpe 大於零，且完整交易次數通過所選回測期間的動態門檻。
  9. 週／雙週／月 K 訊號在高週期 K 棒完整收盤後產生，下一交易日開盤才調整部位。
  10. 多週期條件研究的週、雙週、月、季 K 只採用完整 K 棒；買進與賣出勝率都以次日開盤執行並扣除來回成本。
  11. 附加部位調整先取得原策略目標，再依單日漲跌調整；高波動選項會額外執行一次相同調整，最終曝險限制在 0%～100%。買進持有基準不套用附加層。
  12. 留空結束日代表最新資料；指定結束日後，行情快照、訊號、回測、退場與多週期研究全部截斷於該日，不使用任何之後資料。資料不足完整期間與指標暖機時會拒絕執行。
  13. 定期定額於回測區間第一天及之後每週／每月第一個交易日投入。定期／條件領回可建立至多五條具名規則並調整順序；每條的每 N 個月與帳面門檻是可同時啟用的 OR 條件，同日多條符合時只執行排序最前者。門檻以前一完整交易日的總資產帳面價值／帳面現金跨越「原始投入比例或固定金額」判斷；帳面現金包含另列且尚未投入的現金配息，門檻跌破後才重新待命。下一交易日開盤執行時，總資產模式可賣出持倉並計入賣出成本，帳面現金模式不賣持倉且領回額不超過現金。每次領回可用所選帳面價值的比例或固定金額計算。最低保留資金由獨立開關控制，也可建立至多五條具名規則；它不判斷每 N 個月，只在領回發生時依所選帳面價值由上到下套用第一條「每次」或「達門檻」的下限，沒有符合條件時不加下限。比例模式保留「執行當下所選帳面價值 × 比例」與「起始投入 × 同一比例」較高者，固定金額模式直接保留設定金額，賣出成本也不得侵蝕這次領回的保留底線。投入與領回都屬外部資金流：TWR 在領回執行點前後切分當日報酬再連乘，排除資金流但保留必要賣出成本；最大回撤使用資金流調整後淨值；XIRR 將投入列為負現金流、領回與期末資產列為正現金流。價格獲利固定為「期末價格資產＋由價格帳本支付的領回－起始資金－定期投入」；直接領回配息不會再算一次價格獲利。 這項領回設定適用所有研究標的（包含臺指選擇權），且與商品是否實際配息無關。選擇權總資產模式只能以執行日實際開盤權利金賣出足夠整數口數；沒有可驗證開盤價時不偽造成交。
  14. 自動尋優預設用較早 70% 歷史尋優區間比較 481 種附加方案，使用者可調整左右端，右端最高可到最後一個交易日，區間最短不得少於 2 年。選定後將同一方案套用到完整回測範圍；總報酬、年化報酬、勝率、Sharpe、回撤、品質分、排行榜與資格皆使用完整範圍。自動開啟時手動設定停用且不加入候選；關閉自動後才套用保留的手動參數。
  15. KD 第 9 根日 K 起計算 RSV、K、D；MACD 需完成 26 日慢線與 9 日訊號線暖機後才產生部位，所有訊號皆於次日開盤成交。
  16. 曲線與策略排名採純價格報酬：0050 分割前的價格與成交量會按分割比例還原；^TWII 使用加權價格指數。現金配息依策略在除息日前的實際持有部位另計，不重投、不改變資產曲線與策略排名；儀表板收合摘要另以配息留在現金部位的方式逐日計算含息總報酬、含息年化與相對0050績效。配息為稅前估算，未扣個人稅負與補充保費。
  17. 月 MACD × K 策略只使用已完成的加權指數月 K：MACD（12、26、9）柱狀體負轉正後於下一交易日開盤買進 0050；持有後月 DIF 達 400 且月 K（9,3）達 76 時啟動退場偵測，之後任一跌破門檻即於下一交易日開盤賣出；D 值不參與。
  18. 10% 大漲／大跌高低點必須等反向走勢確認後才能回頭標記，因此只作事件研究，不當成可交易訊號；實際族群策略仍以 T-1 已完成 K 棒產生訊號、T 日開盤成交。
  19. 年度產業權重採前一年底資料避免前視偏誤。電子是半導體、電腦週邊、光電、通信網路、電子零組件、電子通路、資訊服務、其他電子八類合計；金融在 15 年內曾超過 10%，即使 2026 年基準降到 9.68% 仍保留獨立模型；其餘歸入非金電。
  20. 0050、00631L、00632R 各自獨立使用實際行情、上市日、企業行動、成本、基準與工作區。正 2／反 1 是單日曝險目標，跨日報酬會受每日重設、波動耗損與複利路徑影響；歷史行情不得以 0050 日報酬直接乘以 2 或 -1 合成。00631L 的買進持有基準、均線、報酬、RSI、波動與回撤一律標示為 00631L；只有智能策略明確共用的 0050 完成 K 棒與成交量欄位保留「共用指標｜0050」標示。
